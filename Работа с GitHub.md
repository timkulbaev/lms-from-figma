# Работа с GitHub

GitHub — это облачное хранилище для кода. Как Google Диск, только для разработчиков: каждое изменение сохраняется с историей, можно откатиться к любой версии, а агент умеет загружать обновления прямо туда — без лишних действий с вашей стороны.

Большая часть настройки делается через Claude Code — вы по очереди вставляете готовые промпты, агент всё делает сам. Один шаг (регистрация на GitHub) потребует открыть браузер — иначе никак.

---

## Часть 1 — Настройка (один раз)

---

### Шаг 1 — Создайте аккаунт на GitHub (вручную, в браузере)

**Зачем:** GitHub — это сервис, без аккаунта там не работает ничего. Регистрация бесплатная, занимает две минуты.

1. Откройте [github.com](https://github.com) в браузере
2. Нажмите **Sign up** (правый верхний угол)
3. Введите email, пароль и имя пользователя
4. Подтвердите email — GitHub пришлёт письмо

---

### Шаг 2 — Установите Git

**Зачем:** Git — программа, которая отслеживает изменения в файлах. GitHub — это облако поверх Git. Без Git агент не сможет отправлять код на GitHub. Установка разовая — после неё про Git можно забыть.

Откройте Claude Code и вставьте промпт:

```
Проверь, установлен ли у меня Git.
Если не установлен — установи и скажи, когда готово.
Если уже стоит — просто сообщи версию.
```

---

### Шаг 3 — Войдите в GitHub из Claude Code

**Зачем:** агент должен знать, кто вы на GitHub, чтобы создавать репозитории и загружать код от вашего имени. Этот шаг — одноразовая авторизация через браузер. После неё Claude Code работает с вашим GitHub напрямую, без ввода пароля каждый раз.

Вставьте промпт:

```
Войди в мой GitHub аккаунт через gh auth login.
Используй: GitHub.com, HTTPS, войти через браузер.
Когда появится код авторизации — скажи мне.
```

> Агент выведет 8-значный код вида `XXXX-XXXX`. Браузер сам откроется на странице GitHub — введите код и нажмите **Authorize**. После этого вернитесь в Claude Code.

Проверьте результат:

```
Проверь, успешно ли я вошёл в GitHub, и покажи имя аккаунта.
```

---

### Шаг 4 — Создайте репозиторий и сделайте первый коммит

**Зачем:** репозиторий — это папка проекта на GitHub. Первый коммит — это первый «снимок» кода, от которого отсчитывается вся история изменений. После этого шага ваш проект будет виден на github.com.

Вставьте промпт:

```
Сделай следующее для текущего проекта:
1. Инициализируй Git, если ещё не сделано
2. Добавь все файлы и создай первый коммит
3. Создай репозиторий на GitHub — название возьми из имени папки проекта
4. Загрузи код на GitHub
5. Дай мне ссылку на репозиторий
```

> Если у вас ещё нет проекта, добавьте перед остальными пунктами: «Сначала создай папку `my-first-project` с файлом README.md».

После выполнения откройте ссылку из ответа агента — вы увидите свой код на github.com.

---

### Шаг 5 — Убедитесь, что VS Code видит GitHub

**Зачем:** VS Code показывает статус Git прямо в интерфейсе — какие файлы изменились, сколько неотправленных коммитов, на какой ветке вы работаете. Один раз разобраться — и потом читать состояние проекта с первого взгляда.

Откройте VS Code с вашим проектом и найдите эти элементы:

**Панель Source Control (Контроль версий)**
Кнопка с иконкой ветки в левом меню — или нажмите **Ctrl+Shift+G** (Windows) / **Cmd+Shift+G** (Mac).

Что здесь видно:
- **Changes** — список файлов, которые изменились с последнего коммита. Буква `M` = изменён, `U` = новый файл, `D` = удалён.
- Поле ввода вверху — сюда пишется сообщение коммита
- Кнопка **✓ Commit** — создаёт коммит из выбранных изменений
- Кнопка **Sync Changes** (или стрелки ↕) — отправляет коммиты на GitHub и подтягивает чужие

**Строка статуса внизу экрана**
Здесь всегда видно:
- Название текущей ветки (обычно `main`)
- `↑2` — два коммита ещё не отправлено на GitHub
- `↓1` — один коммит пришёл с GitHub, нужно подтянуть

## Часть 2 — Коммиты

Коммит — это сохранённый «снимок» кода в определённый момент. Коммиты живут на вашем компьютере — пока не отправлены на GitHub, существуют только локально.

**Правило:** одно изменение = один коммит. Добавили кнопку — один коммит. Исправили ошибку — отдельный коммит. Так история остаётся понятной.

---

### Сохранить текущие изменения

```
Посмотри, что изменилось в текущем проекте с последнего коммита.
Сохрани все изменения — придумай сообщение коммита сам,
основываясь на том, что реально поменялось в файлах.
```

---

### Сохранить изменения с нужным описанием

Используйте, если хотите сами сформулировать, что было сделано:

```
Сохрани все изменения в текущем проекте в один коммит.
Сообщение: [напишите своими словами, что вы сделали]
```

---

### Посмотреть историю коммитов

```
Покажи последние 10 коммитов в текущем проекте:
дату, автора и сообщение каждого.
```

---

### Что видно в VS Code после коммита

В Source Control панели раздел **Changes** очистится — все изменения сохранены. В строке статуса внизу появится `↑1` — один коммит ждёт отправки на GitHub.

---

## Часть 3 — Пуши

Пуш — это отправка локальных коммитов на GitHub. После пуша код виден на github.com. Без пуша коммиты существуют только у вас на компьютере.

---

### Отправить все коммиты на GitHub

```
Отправь все несохранённые коммиты из текущего проекта на GitHub.
Скажи, сколько коммитов отправлено, и дай ссылку на репозиторий.
```

---

### Подтянуть изменения с GitHub (если работаете с другими)

```
Подтяни последние изменения с GitHub в текущий проект.
Если есть конфликты — покажи их и объясни, как решить.
```

---

### Что видно в VS Code после пуша

В строке статуса цифра `↑` исчезнет — GitHub синхронизирован. Чтобы убедиться — откройте ссылку на репозиторий в браузере: вы увидите обновлённые файлы и сообщение последнего коммита.

---

## Часть 4 — Пул реквесты

Пул реквест (PR) — это предложение добавить изменения в основную ветку, не ломая её сразу. Удобно, когда хотите зафиксировать, что именно и зачем менялось, или попросить кого-то проверить код перед слиянием.

Сценарий: создаёте ветку → вносите изменения → создаёте PR → сливаете в main.

---

### Создать ветку под новую задачу

```
Я собираюсь работать над: [одна фраза — что именно делаете]
Создай для этого ветку с подходящим именем и переключись на неё.
```

---

### Создать пул реквест после изменений

Вставьте после того, как внесли изменения на новой ветке:

```
Я закончил изменения на текущей ветке.
Сохрани их, если ещё не сохранено.
Создай пул реквест — заголовок и описание придумай сам по коммитам этой ветки.
Дай мне ссылку.
```

---

### Слить пул реквест в main

```
Слей последний открытый PR в main, удали ветку и подтяни обновлённый main на мой компьютер.
```

---

### Посмотреть открытые пул реквесты

```
Покажи все открытые пул реквесты в текущем репозитории:
заголовок, дату и ссылку для каждого.
```

---

### Что видно в VS Code при работе с PR

**Ветка в строке статуса:** вместо `main` будет имя вашей ветки. Кликните на него — откроется список всех веток с возможностью переключиться.

---

## Быстрые промпты на каждый день

**Что изменилось и что не отправлено:**
```
Покажи статус текущего проекта:
что изменилось, сколько коммитов не отправлено и на какой ветке я нахожусь.
```

**Сохранить и отправить за один шаг:**
```
Сохрани все изменения в текущем проекте в коммит —
придумай сообщение сам по изменениям — и сразу отправь на GitHub.
```

**Откатить последний коммит (если ещё не отправили на GitHub):**
```
Отмени последний коммит в текущем проекте,
но оставь изменения в файлах — я хочу их переделать.
```

**Посмотреть, что изменилось в файлах:**
```
Покажи, что изменилось в текущем проекте с последнего коммита — по файлам.
```

**Получить ссылку на репозиторий:**
```
Дай ссылку на GitHub-репозиторий текущего проекта.
```

---

> **Напоминание:** Git хранит историю на вашем компьютере, GitHub — в облаке. Коммит = сохранить локально. Пуш = отправить в облако. Без пуша GitHub не знает о ваших коммитах — делайте пуш в конце каждой рабочей сессии.
